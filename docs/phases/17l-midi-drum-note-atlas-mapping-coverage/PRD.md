# PRD — Phase 17L: MIDI Drum Note Atlas and Mapping Coverage

## Problem

CHDG currently uses a small flat MIDI mapping table. Known percussion notes outside the current table can become `unknown`, causing warnings and skipped notes even when the note meaning is known. Conversely, some notes that are technically General MIDI drum notes should not be auto-charted because they represent auxiliary percussion, foot actions, or sounds that do not map cleanly to Clone Hero drum lanes.

## Goals

1. Make MIDI drum mapping decisions explicit and auditable.
2. Expand coverage for General MIDI and GM2/GS percussion note numbers.
3. Prevent known auxiliary percussion from being treated as unknown errors.
4. Avoid over-charting uncertain notes by making candidates visible but non-generated by default.
5. Give Source Review enough information to explain what CHDG did.
6. Preserve existing project override capability.
7. Prepare the model for future GPIF articulation mapping without implementing that full scope now.

## Non-goals

- Do not redesign the full Mapping Review UI.
- Do not implement a manual editor beyond existing override capabilities.
- Do not implement a candidate-aggressive mapping profile.
- Do not implement GPIF articulation metadata extraction in full.
- Do not change tempo map, Preview, Generate layout, or section behavior.

## Users

Primary user: a CHDG user importing MIDI or Guitar Pro drum sources and expecting the resulting chart to preserve relevant drum performance while avoiding noisy auxiliary percussion.

## User stories

### As a user importing a MIDI drum track

I want CHDG to understand common percussion notes so I do not get confusing unknown-note warnings for known GM/GM2 percussion.

### As a user reviewing mappings

I want to know which notes were auto-mapped, which were ignored as known auxiliary percussion, which need review, and which are truly unknown.

### As a user generating a chart

I want candidate notes to be skipped unless I explicitly map them, so the chart does not become over-charted with questionable percussion.

### As a user with a foot hi-hat-heavy MIDI

I want `44 Pedal Hi-Hat` to be reviewed rather than silently auto-charted as a hand hi-hat, because foot chicks can create over-dense patterns or impossible hand situations.

## Functional requirements

### F1 — Rich MIDI drum note atlas

Replace the flat note-to-piece mapping with entries containing at least:

- `note`: MIDI note number.
- `name`: display name.
- `action`: `map`, `candidate`, `ignore`, or `unknown`.
- `piece`: required for `map`; optional suggestion for `candidate`.
- `confidence`: `high`, `medium`, or `low`.
- `family`: semantic family such as `kick`, `snare`, `hihat`, `tom`, `cymbal`, `aux-percussion`, `fx`, `metronome`, `digital`, `unknown`.
- `source`: `gm`, `gm2`, `gs`, `profile`, or future-compatible value.
- `reason`: short human-readable explanation.

No compatibility with the old flat JSON format is required.

### F2 — Atlas version

Introduce a mapping atlas version string:

```text
0.1.0
```

Use this version in analysis/cache fingerprinting so old cached Source Review/normalization results are invalidated when atlas behavior changes.

### F3 — Normalization behavior

For MIDI note resolution:

- `map`: create `DrumHit` with the atlas piece.
- `candidate`: do not create `DrumHit` by default; record coverage/candidate metadata.
- `ignore`: do not create `DrumHit`; record ignored known percussion metadata.
- unknown note: do not create `DrumHit`; record unknown metadata and issue.

Project overrides must remain authoritative:

1. If an override maps a candidate/ignored/unknown note to a piece, create hits for that note.
2. If an override ignores an auto-mapped note, do not create hits for that note.
3. If no override exists, use atlas action.

### F4 — Coverage summary

Add coverage data to `NormalizationPreview`, persisted in `.chdg`, containing at least:

- total MIDI note events inspected.
- auto-mapped hit count.
- candidate hit count skipped by default.
- ignored known percussion hit count.
- unknown hit count.
- number of unique auto-mapped sources.
- number of unique candidate sources.
- number of unique ignored sources.
- number of unique unknown sources.
- atlas version used.

### F5 — Mapping candidates / entries

Extend mapping candidate rows to include entries for mapped, candidate, ignored, and unknown sources. Rows should include:

- key.
- source kind.
- source value.
- display name.
- action.
- automatic/suggested piece if available.
- confidence.
- family.
- source standard/profile.
- count.
- first tick.
- reason.
- status suitable for Source Review.

### F6 — Minimal Source Review UI

Without redesigning Mapping Review, show enough coverage to make the new behavior visible:

- compact summary: mapped / candidates / ignored / unknown.
- issue/status wording that distinguishes ignored known percussion from unknown notes.
- existing override mechanism should still allow map/ignore actions.

Full filters/table redesign are out of scope and deferred to 17M.

### F7 — Generate issues

Generate should not fail because of candidate, ignored, or unknown notes.

Severity guidance:

- ignored known percussion: `info` or summary only, not warning.
- unresolved candidate: `info` or `warning`, non-blocking.
- unknown: `warning`, non-blocking.

### F8 — Foot hi-hat 44

`44 Pedal Hi-Hat` must be `candidate -> hihat_closed`, not auto-map.

Reason: Pedal hi-hat is a foot action and may not represent a playable hand note; auto-charting it can over-densify parts or create more-than-two-hand situations.

### F9 — Candidate default rule

Candidates do not generate notes by default. This is a stable base behavior. A future aggressive profile may choose to auto-map candidates, but that is explicitly out of scope.

### F10 — Future GPIF compatibility

Do not implement advanced GPIF articulation mapping now. Add model design that does not prevent a future GPIF articulation phase from using articulation name, input MIDI numbers, output MIDI number, and element/family metadata.

## Acceptance criteria

1. The atlas covers GM 35–81 and extended 27–34 / 82–87 entries.
2. The atlas uses rich entries, not flat note-to-piece strings.
3. Safe mappings auto-generate hits.
4. Candidate notes do not auto-generate hits.
5. Ignored known percussion does not auto-generate hits and does not produce noisy unknown warnings.
6. Unknown notes remain visible and non-blocking.
7. Project overrides can map or ignore any source supported by the mapping key model.
8. `44 Pedal Hi-Hat` is candidate, not auto-map.
9. Coverage summary is present in normalization preview and persisted in `.chdg`.
10. Mapping atlas version `0.1.0` is included in cache/fingerprint logic.
11. Existing Generate/Preview/sections behavior remains unchanged.
12. Tests cover atlas resolution, normalization behavior, coverage summary, overrides, cache versioning, and minimal UI/source review output.
